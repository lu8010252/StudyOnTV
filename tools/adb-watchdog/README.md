# 投影外部看门（adb-watchdog）

在机顶盒（Armbian + 1Panel）上跑，通过 ADB 看管投影里的「题了个题」：

- 应用进程不在：先等 15 秒（给应用自己的自唤醒机会），还不在就给应用的自唤醒接收器发广播拉起（服务本身不对外开放，shell 直接启动会被拒绝）
- 无障碍服务被关：写回 `enabled_accessibility_services`
- 以上两种情况都会推送到 ntfy；投影关机/离线时只做一次端口探测，不跑 adb

部署：1Panel → 容器 → 编排 → 新建，粘贴 `docker-compose.yml`，按需改 `TV` / `NTFY`。
首次启动后在投影上点「允许 USB 调试」并勾选「始终允许」（密钥存在 `./adbkey`）。
前提：投影的 ADB 网络调试（5555）要一直开着。

这是应用自带保活之外的一层保险，不能替代应用里的保活。

## 更新后怎么确认跑的是新版

脚本是内嵌在 compose 里的，**改了仓库不会自动更新机顶盒上的容器**：要把新的 `docker-compose.yml` 重新贴进 1Panel 编排并「重建」。
重建后看容器日志第一行，应显示 `启动 v2.1：看管 …`；如果还是 `启动：看管 …`（没有 v 号），说明跑的仍是旧脚本。
旧脚本的特征是通知「应用进程不在，拉起失败（检查投影 ADB 授权）」——它用 shell 直接启动不对外开放的服务，必然被拒，但应用自己的自唤醒其实已经把它拉起来了，属于误报。

- v2.1：连续拉起失败只通知一次（恢复后重新计）；广播加 `-f 32`；失败时日志写明进程/服务哪个没了
- v2.0：改为给 ReviveReceiver 发广播拉起，同时检查 GateService
